Containers

Every chat's container. stop ends the running Pi and stops the container (the chat resumes on its next message, with what was installed). recreate also removes the container, so the next message builds a clean one and the conversation continues. remove ends the chat and removes the container; its workspace stays. update rebuilds it with today’s settings keeping what is installed, sets Pi to the gateway’s version and updates its extensions (a newly built image is only taken by recreate).

Piper …

            
An OpenAI-compatible gateway that runs the Pi coding agent, one container per chat.

          

        

      

      

        

          
What it is

          
Piper puts the Pi coding agent behind the OpenAI API. Point any OpenAI client at it and every conversation gets its own agent, running inside its own Docker container with full rights there and nothing of the host that you did not give it.

          
    
            
  • Isolated by design. One container per chat, a network policy that keeps the host and the LAN out, and provider credentials that never enter a container.
    • 
            
  • Per-key everything. Each API key has its own skills, extensions, settings, workspace, limits and spend; a key can be given a container that lasts.
    • 
            
  • Agent endpoints. Named, permanent agents (an architect, a coder, a researcher) each on an OpenAI-compatible port of its own.
    • 
            
  • Run it properly. Container control, updates, backups, alerts, a watchdog, an audit log and resource charts, all in this dashboard.
    •

Agent endpoints

            
A named, permanent Pi agent of an API key with a port of its own: point any OpenAI client at its URL with the key it belongs to. Each has its own instructions, skills, model and container (kept between chats), so one key can front an architect, a coder and a researcher. Spend, session and model limits stay on the key.

Teams

            
A team is a chain of agents of one key behind an endpoint of its own. A request runs the steps in order: each step’s instruction gets {{task}} (what was asked) and {{previous}} (the last step’s answer); the last answer is the reply, and progress streams as reasoning. Spend and limits are the key’s.

Templates and import

            
A template is a ready-made profile: instructions, skills and settings. Pick one when creating an agent, or save an existing agent as a template (the save as template button). The orchestrator template turns hand-offs on: it sees every enabled agent of its key, with its description, at the start of each turn, so write a good description on each agent. An agent can also be exported to a file and imported into any key, here or on another gateway.

A bundle can carry extensions, which are code that runs in the agent’s container: import only files you trust. Needs a dashboard password. Environment, mounts, images and network are never part of a bundle.
